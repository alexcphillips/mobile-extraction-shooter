# Tech stack: Overview

Part of the [tech-stack.md index](../tech-stack.md). Record decisions here, in the topic they belong to.

## Platform: a mobile web game, not React Native
React Native / Expo Go was considered and rejected:
- Hermes (React Native's JS engine) has no JIT and no WebAssembly, so game logic would run slowly.
- `expo-gl` puts rendering and game logic on one JS thread.
- Expo Go locks you to a fixed SDK and set of native modules.

Mobile Safari has a JIT and WebAssembly, needs no build step and no Apple developer account, and installs from Add to Home Screen. Every iOS browser uses Safari's engine underneath, so Chrome on iOS makes no difference.

**An App Store build later (2026-11-12, roadmap MZ-2): the same client in a native shell, not a rewrite.** Capacitor around WKWebView, which is Safari's engine with the JIT, so it runs as well as the home-screen version. The client is **bundled in the app**, never loaded from our URL (that reads as a website wrapper under Apple's guideline 4.2, and changes the app outside review). What has to change first:
- **API and sign-in:** the client calls `/api` on its own address and signs in with a same-origin `SameSite=Lax` cookie (`account.ts`, `server/src/auth.ts`). A bundled app's page lives at `capacitor://localhost`, so the cookie isn't sent. Fix: an API base URL, a bearer token for the app (the cookie stays for the web), and CORS for the app's address. Do it before more server code depends on the cookie.
- **Old clients:** each client change waits for review and some players won't update, so the server needs a minimum client version (old apps told to update), and content and save formats stay compatible across a few versions. Once there are store players, "wipe instead of migrating" ends.
- **Native polish:** landscape lock, hidden status bar and home indicator, safe areas; audio unlock and the gamepad API checked in WKWebView.
- **Apple's requirements:** a developer account ($99 a year), in-app account deletion, a privacy policy and privacy labels, Apple's in-app purchase for anything sold, and account recovery (email or Sign in with Apple) since paid accounts can't sit behind a password with no reset.

## Repo layout (npm workspaces monorepo)
npm, not pnpm (the user's choice, 2026-10-26). Each package lists every dependency it imports, since npm won't catch a package using a dependency that only another package declared.

Tooling (session 1):
- `@mes/shared`, `@mes/client` and `@mes/server` are the package names. `shared` has no build step: it exports its TypeScript source, and Vite and wrangler bundle it.
- TypeScript is **pinned to 6.0.x**, because typescript-eslint doesn't support TypeScript 7 yet. Move to 7 once it does.
- `shared`'s tsconfig leaves out the DOM types, and ESLint blocks imports of three.js, React and the other packages from it, so the "no rendering or UI in the simulation" rule is enforced, not just written down.
- Strict TypeScript, including `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`.
- One root ESLint (flat config) + Prettier setup. Vitest runs every package as a project from the root.
```
packages/
  shared/    # game simulation, rules, data schemas. No three.js, React or DOM.
  client/    # Vite app: three.js renderer, React UI, input; includes /editor
  server/    # Cloudflare Worker
content/     # JSON game data: maps, prefabs, items, loot tables, quests, vendors, enemies
docs/
```

## Raid lifecycle
Session 11, `sim/raid.ts`. See design.md → Raids and maps → Extraction.
- `SimState.raid` (`RaidState`: the tick the timer runs out on, and the extraction points from the map's extraction zones since map format 4; before, its markers) is set by `startRaid`, and null outside a raid (tests, the perf scene), where nothing below happens. `Character.extracting` counts the seconds a player has stood in an extraction point (within its radius across, and `RAID.extractHeight` up or down).
- `updateRaid` runs last in `step`, after the tick count goes up. A living player who reaches `RAID.extractTime` (7 s) leaves; when the timer runs out, every living player still in the raid leaves as missing in action. **A player who leaves is taken out of `state.entities`** and kept in `state.left` (`LeftRaid`: the character with all its gear, how, where, and the tick), with a `leave` event. So nothing can shoot or follow them, and enemies who were after them calm down (they already handle a target that no longer exists). Enemies never leave. The dead stay in `entities` as bodies.
- `gearItems(gear)` lists everything a character carries; `keptItems(gear, survived)` is what a player keeps (everything after extracting; otherwise the knife and the vault). Session 12's raid end will send these.

## Hosting and testing
- **One Worker serves both the client and the API** (decided 2026-10-26, session 1). The built client is the Worker's static assets (`packages/server/wrangler.jsonc` points at `packages/client/dist`). Only `/api/*` runs Worker code; any other unknown path falls back to `index.html`. Sharing one origin means no CORS, and session cookies work with no extra setup. Pages was the alternative; Cloudflare is moving new projects to Workers static assets anyway.
- In dev, the client (Vite, port 5180) and the Worker (`wrangler dev`, port 8787) run separately, and Vite proxies `/api` to the Worker. `wrangler dev` refuses to start if the assets folder is missing, and `dist` is gitignored, so the server's `predev` creates an empty `packages/client/dist` (decided 2026-10-30). A fresh clone runs `npm run dev` without building first.
- **Phone testing during development:** run `vite --host` and open it on the iPhone over the local network. When HTTPS is needed (installing as a home-screen app, some browser features), use a Cloudflare preview deployment or a `cloudflared` tunnel.
- Each milestone ends with a performance check on the real iPhone (FPS counter in dev builds).
- **Screenshots for Claude (2026-11-09, the user's request):** `npm run look -- [--phone] [--click <selector>]... --out <file.png>` (`scripts/look.mjs`) opens the dev server in headless Chromium (Playwright, a dev dependency), signs in as the local test account `claude-test` (registered on first use, on the local dev database only; the script refuses any host that isn't this machine or the LAN), does the clicks and saves a screenshot. `--phone` is an iPhone 15 held sideways (touch, no hover), which the inventory lays out differently from a PC; `--fresh` uses a new account with a new character's kit. It needs `npm run dev` (both servers) running, and `npx playwright install chromium` once per machine. It's for looking at UI, not a replacement for testing on the real iPhone.

## Characters (confirmed, see design.md → Characters)
- The base body is a rigged, animated low-poly humanoid from a CC0 pack in glTF format. Recolor it to flat colors and draw it unlit, so it matches the map.
- Gear (helmet, armor, rig, backpack, weapon) is built in the item editor and attached to the skeleton at named mount points (`MOUNTS`: rigs on the armor's bone). Rigs are drawn since session 18b.
- Hit zones are simple capsules, not tests against the mesh itself. **They're a fixed layout in the simulation, not attached to bones** (changed 2026-10-26, session 6, so a co-op server needs no skeleton); the body is drawn to match.
- Distant characters update their animation less often to save performance.

Built in session 8b:
- **The asset:** `packages/client/public/characters/mannequin.glb`, from Quaternius's Universal Animation Library (Standard, CC0; license and source in the README next to it). `scripts/build-character.mjs` builds it from the pack's GLB with glTF Transform and meshoptimizer: 15 clips kept, UVs dropped, the mesh simplified from 13.7k to 5.8k triangles, only rotation tracks kept (plus the hips' translation). 556 kB, 279 kB gzipped, fetched at startup rather than bundled. Quaternius's site moved new downloads to its own license (QAL, August 2026), which forbids redistributing the files; this copy is CC0, but check before adding later downloads to the public repo.
- **One draw call per character, gear included** (`render/character.ts`). At load, the body is baked into flat triangles with face normals; each face takes the outfit part of the bone that weighs on it most (joint bands 20% darker). Each look (outfit, worn items, gun) is one geometry, built once and cached, with gear bound rigidly to its mount bone. Shading happens on the GPU from the skinned normal, with the same formula as the map. Bodies cull by a fixed sphere, since animation moves them far from their rest-pose bounds.
- **Animation** (`render/character-body.ts`): two layers, legs and upper body, from clips split by bone. The legs pick idle, walk, jog, sprint, crouch, crouch walk, jump or death by speed and stance, paced to the speed. When strafing, the hips turn towards where it's going (up to about 70°) and the chest turns back to face forward; going backwards plays the clip in reverse. The upper body leans with the look pitch and flinches when hit. **Leaning** (2026-11-01) turns the lower and upper spine (60/40) about the body's forward axis by the sim's lean angle, smoothed, and cants the gun by the same angle; the IK'd arms follow the shoulder. `CapsuleBody` tips its upper capsules about the same pivot, so `/bodies` (poses "lean left/right aimed", "crouch lean right") and `?hitzones` show them matching. **Gun hold by IK:** a two-bone IK per arm, with the hand rotations measured once from the pistol aim clip. The gun's position and tilt per hold are in `HOLD` there.
- **three.js's mixer only writes a bone when its clip value changes**, so posing on top of clips must put each bone back to its clip rotation before every update; otherwise turns pile up frame after frame. `CharacterBody` does this for the bones it poses.
- **LOD:** a body animates every frame within 20 m, every 2nd frame to 45 m, every 4th beyond, and every 8th off screen. It uses IK within 30 m; beyond that the gun goes in the hand. The dead stop animating 3 s after falling. Positions and yaw are interpolated between ticks.
- `/bodies` shows every pose with the hit zones over them, and `?hitzones` does the same in play.

Our own skeleton and player (CH-1, 2026-11-13; behind `?body=own` until CH-5, nothing draws it yet):
- **Data:** `content/characters/skeleton.json` and clips in `content/animations/` (schemas in shared `content/skeleton.ts`; client loaders `loadSkeleton`, `loadClips`; the server doesn't bundle them). 17 bones (`SKELETON_BONES`, parents first): hips, spine, chest, neck, head, and upperArm/forearm/hand, thigh/shin/foot + L/R. Meters, facing −z, +x the body's right, feet on y = 0. **The rest pose is a T-pose with every rest rotation the identity**, so offsets are plain translations and anything modeled on the rest pose is in world axes. Rotations are degrees `[x, y, z]` in Euler order `YXZ`, as in maps. Limits per bone are first guesses for CH-4's checks. Mounts: helmet on head; armor, rig and backpack on chest (one chest bone now, where the pack had two). `headVolume` is the sim's head capsule in the head bone's frame; a test keeps them equal. Every hit zone is fitted to this skeleton (see design/damage-and-health.md → Hit zones).
- **Clips:** `layer` lower (hips, legs, and the hips' `move`) or upper (the rest), checked by the schema; keys are `[t, x, y, z]` rows per bone; a loop blends its last key into its first across the seam. `compileClip` turns keys into quaternions once.
- **Player** (`render/skeleton-pose.ts`): `Pose` holds local quaternions and writes `world` and `skin` matrices (Float32Array, 16 per bone; skin = world · translate(−rest), the matrix for rigid pieces and gear) and a `weapon` matrix for the gun. `applyClip(clip, t, weight)` blends over what's there; `ClipLayer` crossfades. `reach` (the pack body's two-bone IK), `holdGun`, `carryGun` with `gunInHand` (the hand-on-grip inverted, so a carried gun sits as a held one) are ported to our bone names. `holdKnife(pose, grip, slash?)` holds the knife ready (`KNIFE.ready`: right wrist low by the hip, tipped 0.35 up; `KNIFE.guard`: left hand up in front of the chest) or slashes (a curve through `KNIFE.slash`'s start by the right shoulder, middle across the front at full stretch, end low on the left, the blade turning from 0.7 rad right to 0.9 left). `armsDown` hangs empty hands (`ARMS_DOWN`, elbows back). **The sim's arm zones per hold are fitted to these poses** (design/damage-and-health.md → Hit zones), so the idle and stance clips of CH-5 should match `armsDown`, or the zone test should measure from the clips instead. Nothing allocates per frame. `BODY_BONES` (plating) still names the pack's 20 bones; CH-2 maps them on (belly → spine, upperChest → chest, toe → foot).
- **The hold (`holdGun`, `HOLD`, retuned 2026-11-13):** aimed, the gun's `sight` point sits 7 cm right of and 2 cm under the eye (the neck joint + 0.12 up, 0.09 forward), as the first-person view puts sights on the eye line. A rifle's butt (0.33 m behind its grip, a length of pull) goes 6 cm in front of the right shoulder joint, and the chest turns 29° right (spine and chest share it; the neck turns the head back) so the support hand reaches. The low ready tips a rifle 0.6 rad down about its butt; a pistol is pushed out to 0.42 m ahead of the eye aimed and pulled in to the chest at the low ready. The upper body leans with 0.4 of the look pitch, and the gun turns about the eye aimed (the shoulder at the low ready), so aimed sights stay on the look. **A support point out of reach** slides back along the gun to where the arm reaches (`slideInReach`): at most 6 cm at normal look angles, 17 cm on the MP-133 aimed 46° up. Arms are 0.30 + 0.26 m to the wrist.
- **The body (CH-2, 2026-11-13):** `content/characters/body.json` (`bodySchema` in shared `content/skeleton.ts`; `loadBody`, and `bodySource` for the editor): `colors` (the outfit it's authored in) and `model.parts`, item-model parts in the rest pose whose `group` is their bone. 40 parts, 760 triangles (budget 800). `render/body-model.ts`: `bodyGeometry(body, skeleton, outfit, gear, items)` builds one look as ONE skinned geometry (every vertex on one bone, weight 1): body parts tinted per channel by their bone's outfit slot (`outfitSlotOf`: head and neck skin, hands, feet, hips and legs bottom, the rest top; outfit color over `colors`, so shades keep their ratios), the outfit's plating (`PLATING_TO_SKELETON` maps the pack's bone names: belly → spine, upperChest → chest, toe → foot) and worn gear on its mount bone. A helmet with `hidesHead` (Jug's mask) leaves the head parts out. `BodyMesh` is a `SkinnedMesh` whose bones are its children, each set to the pose's world matrix, with inverse binds of −rest, so the GPU applies the skin matrices; it uses the pack's `characterMaterial` (now exported). Nothing in the game draws it yet (CH-5).
- **The fit check (CH-3, 2026-11-13):** `render/fit-check.ts`, run by `node scripts/anim-check.mjs --fit` (`--kit slot=id,…`, `--each`, `--outfit scav-2`, `--where`) and tested in `fit-check.test.ts`. Every model part is convex (box, wedge, slab, cylinder), so a part is its face planes and "inside" is exact. Per worn piece and test pose (`FIT_POSES`: T, arms down, the rifle low, aimed, up and down, the pistol, knife ready and mid-slash, a rough crouch, the head turned; clips replace them from CH-5): **through** is a covered surface (head under head gear; neck, chest, spine and hips under torso gear; gear worn under it, `UNDER`) outside the gear with one of the gear's *outside* faces (turned away from the head's middle, or from the chest's upright line) within 5 cm under it (2 cm for gear under gear), probed along the surface's normal and stopped where the surface's own part ends or another part on its bone starts; a surface inside anything worn on the same mount is hidden. **into** is a limb, the gun or a piece beside it (helmet and visor, helmet and carrier) sunk into the piece: the deepest point (capped by the piece's thickness) and the area sunk in, cm². A `(chest)` row measures arms and gun sunk into the bare torso, so gear can be told from the hold. Surfaces sampled at the middles of 2 cm triangles, never on edges; faces buried in another part of the same piece left out. About a second for the kit.
- **Worn gear on our body** (`WornGear`, `MOUNT_OF`): helmet, the visor fitted to it and the headset on the helmet's mount (the head); armor, rig and backpack on theirs (the chest). `/bodies?body=own` (`bodies/own.ts`) draws our body in the fit poses wearing the test kit (`FIT_KIT`; `?kit=helmet=steel-helmet,visor=`, `?bare`, `?outfit=scav-2`, `?focus=n`, `?close`), with the held gun or knife.
- **Arms that clear the torso and gear (CH-3c, 2026-11-13):** `clearArms(pose, layer, free)` in `skeleton-pose.ts`, called at the end of `holdGun`, `holdKnife` and `armsDown` (each takes a `layer`, default `bare`). The torso is rounded boxes in the chest bone's frame: `TORSO` (pelvis, waist, ribs, matched to the body), plus `LAYER_BOXES.armor` and `.rig` (the layer envelopes, props.md → Fitting worn gear). Each arm is sampled past `SHOULDER_CAP` (45% of the upper arm: under the shoulder it rests on the ribs, as arms do) at radii 4.7 and 4.5 cm. A free (hanging) arm is raised out about the shoulder 2° at a time until it clears; then any arm swings its elbow round the shoulder–wrist line (±120°, 10° steps, least turn preferred) with the hand kept where it is. Guns are held off the chest by `STAND_OFF` (armor 4 cm, rig 9 cm at the low ready, a third aimed). Nothing allocates per frame. Left: the support arm brushes the outer rig pouch at the low ready (2.5 cm).
- **Model parts `loft` and `hull` (CH-3a):** shared `content/hull.ts` (`convexHull`, `loftRing`, `loftPieces`); `ModelShape` (compile.ts) is a map `Shape` or one of them, so map code is untouched; `TriangleBuilder.shape` draws them (a loft's sides wound away from each segment's middle, ends capped); the fit check splits a loft into convex segments; mirroring flips the part's own frame (enemies.ts `mirrorShape`, the item editor's `mirrorPart`).
- **Hands on the gun** (`HANDS`): rough wrist offsets and turns, not measured from a clip; CH-6 tunes them with the aim pose.
