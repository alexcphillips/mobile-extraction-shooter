# Tech stack: Items and inventory

Part of the [tech-stack.md index](../tech-stack.md). Record decisions here, in the topic they belong to.

## Item format
Started in session 6 with what combat needs; session 6b added attachments (format 2), session 9 the rest of the item types and grid sizes (format 3), and session 10b draw times and the knife's stats (format 4). The schema is `packages/shared/src/content/items.ts`, whose comments are the field-by-field reference.
- **Files:** `content/items/<id>.json`, one item each, loaded like maps (`formatVersion`, migrations, strict zod objects). The `type` field picks the kind: `weapon`, `ammo`, `armor`, `attachment`, `med`, `container`, `melee`, `grenade`, `key`, `quest`, `loot` or `repair`.
- **Every item** has `weight` (format 11, BW-3): kg for one (a stack's is per one), a gun's bare (attachments and rounds weigh their own), a bag's and carrier's empty; 0 for admin tools and zombie claws. Format 10 → 11 guesses it by type (`weightGuess`, which the item editor's new items use too) and keeps one already set. `sim/weight.ts` adds them up (`itemWeight`, `gearWeight`) into `Character.load`.
- **Every item** has `size`, `[width, height]` in grid cells, unrotated. Only `ammo` (required) and `loot` (optional) have `stack`, the most in one cell.
- Format 2 → 3 (session 9) guesses a size from the type (rifle-held guns 4×2, pistols 2×1, helmets 2×2, body armor 3×3, anything else 1×1) and gives ammo a stack of 60.
- **med:** `effect` (`bandage`, `splint`, `surgery` or `heal`), `useTime`, `uses` (default 1; not for heal) and, for heal only, `hp` (its pool). One effect per item keeps the heal button's choice simple.
- **container:** `slot` (`rig` or `backpack`) and `grid`, the size inside. **key:** optional `uses` (session 11c; an item instance keeps what's left in `left`, like meds); no format change, as it's optional. **quest** and **loot** have nothing else yet.
- **melee** (the knife, format 4): `damage`, `level` and `armorDamage` (format 9, as for ammo), `bleedChance`, `swingTime` (seconds between swings), `reach` (meters from the eye) and `drawTime`.
- Format 3 → 4 (session 10b) gives weapons a `drawTime` by hold (pistol 0.4 s, otherwise 0.8 s) and melee items the knife's first-guess stats. **repair:** `points`, the durability it can restore in all (used from session 13).
- **Format 4 → 5 (session 13b):** every item has a **`value`** (whole money, 0 or more: what vendors sell it for; see design.md → Economy); **loot** may have **`money: true`** (cash: deposited at full value); **repair** gained **`useTime`** (seconds, in a raid). The migration guesses a value by type and gives repair kits 8 s; the content files set their own.
- **Sounds (format 7, session 19):** `weapon` has `sounds: { shot, suppressed, reload }`, `melee` `{ swing }`, `med` and `repair` `{ use }`, each a sound file's id (`content/sounds/`). `defaultSounds` gives the first ones by hold or effect; format 6 → 7 uses it, as do blank and test items. `checkSounds` (`content/sounds.ts`) checks every sound an item names exists, and every sound the game plays itself (`GAME_SOUNDS`, client `audio/sound-ids.ts`); `loadSounds` runs it, and so does the item editor's `itemContentProblem`. The server doesn't load sounds. The content files were rewritten at format 7, except `assault-rifle.json`, which had the user's uncommitted edits (the migration gives it the same sounds); it was brought up to format 8 with the rarities, its sounds written in and its model edits left as they were.
- **Rarity (format 8):** every item has `rarity`: `common`, `uncommon`, `rare`, `epic`, `legendary` or `mythic` (`RARITIES`; the two new ones stayed at format 9, as no file changes), after `value` in the files. Format 7 → 8 makes them all common; blank items start common. The client colors tiles by it (`colorOf` in `ui/raid-screen.tsx`, also the vendors page and the item editor's swatches); the item editor has a picker. Since 2026-11-09 `checkItems` holds it to design.md's rules: weapons and attachments common (`COMMON_TYPES`), and, until 2026-11-11, rigs and backpacks by cells; since then the item editor only fills a bag's rarity in from its slots when they change (`fillBagRarity` in `item-editor/editor.ts`, `bagRarity`, `BAG_RARITY_CELLS`), and it can be overridden. Quick equip's armor pick and the stash's rarity sort read it too. The editor's auto-fill is `fillRarity`: armor and armored rigs by armor level (`levelRarity`), other bags by slots.
- **Armored rigs (2026-11-11):** `ContainerDef.armor` (rigs only, no format change: it's optional). Code that wants "armor" asks `armorOf(def)` / `armorStatsOf(items, id)` (armor's stats, or an armored rig's), and the chest's is `chestArmor(items, gear)` (body armor, else an armored rig). A worn or stored armored rig carries `durability`/`max` like armor (`createItem`, `checkItem`, `settleBags` adds or drops them when content changes, and moves body armor worn under a newly armored rig to the stash). `gearConflict(items, gear, slot, item)` is the one rule for "not both", checked by `swapSlot`/`quickMove` in looting, `checkGear`, starting kits, loadouts and the client's drag (`refused` on DragHost shows the reason).
- **Levels (format 9, 2026-10-30; design.md → Ammo and armor levels):** `ammo` has **`caliber`** (any string; guns fire every round of their own round's caliber) and **`level`** (1–`LEVELS`, 6), and `armorDamage` is now required and means **durability per hit** (per pellet). `armor` has **`level`** in place of `absorb`. `melee` has `level` and `armorDamage`. Format 8 → 9 makes each old round its own caliber at level 1 with armor damage ×10, guesses armor's level from `absorb` (×6, rounded), and gives knives level 1 and armor damage 5. `caliberOf` and `firesRound` (`content/items.ts`) answer which guns fire what. The hit itself is `shootCharacter` with `ARMOR`, `throughArmor` and `armorWear` (`sim/health.ts`). Every item file was bumped by its version line only, so the diffs stay small; the rounds, armor and knife were rewritten.
  - **The round in a gun** is `Item.loaded` (an ammo id of its caliber), left out while it's the gun's own round, so saved guns stay valid. `WeaponState.reloadWith` is the round a reload in progress loads (`restGear` clears it). `loadedAmmo(items, gun)` reads it; `reloadRound(c, items, w, want?)` picks what a reload loads (the round asked for if carried, else the one loaded, else the highest level carried; no allocation). A reload of another round swaps: new rounds are taken first, then the old ones stowed, or dropped with no room. `PlayerInput.ammo` asks for a round with `reload`. Everything that counted a gun's rounds as `WeaponDef.ammo` (unload, magazine changes, sell price, `countItems`) uses `loadedAmmo`, and `checkProfile` refuses a `loaded` round the gun doesn't fire.
  - **Loading by drag:** the inventory action `{ type: 'load', gun, from }`. `loadKind(state, c, items, gun, from, instant)` (`sim/looting.ts`) says what it would do: `'reload'` onto the gun in hand in a raid (sets `reloading` and `reloadWith`, so `finishReload` takes the rounds from what's carried), `'load'` at once elsewhere, or null; `loadGun` does it. The stash calls `loadGun` with `instant` true. The client's `gunZone` gives rounds a `load` drop zone on any `data-gun` element and asks `loadKind` whether it's green, so the outline and the sim agree.
  - **Loadouts** may list `ammo` per weapon (`[{ weight, item }]`): the round it's loaded with and carries spares of; `checkEnemies` checks the gun fires each. AI reloads whenever `reloadRound` finds anything, so an enemy out of its own round switches to another it carries.
  - Client: `ui/levels.ts` (the level colors, `levelOf`), a level tag on ammo and armor tiles (removed 2026-11-09: rarity color says it), the ammo readout's round name with its level color, and the reload button's long press opening `HandsHud.showAmmoPicker` (removed 2026-10-30: rounds are chosen by dragging them onto the gun). The item editor has caliber and level fields, lists the guns that fire a round, and warns that a changed caliber can break saved guns.
- Not in item files yet: icons for the inventory screen (tiles are colored by type). Icons drawn from the models were left out of session 18b: rendering them on the phone at startup is its own problem.
- **grenade** (2026-10-30, still format 9: a new type changes no existing file): `fuse` (seconds from the throw), `throwSpeed` (m/s), `radius` (meters), `damage` (to the chest at the center; other zones take `GRENADE.zones` of it), `level`, `armorDamage` and `bleedChance` (as for ammo, per zone hit), `loudness` (AI hearing, meters), and `sounds: { throw, bounce, explode }`. The simulation is `sim/grenades.ts`: thrown grenades are `SimState.grenades`, plain data like the rest of the state. Each tick a grenade falls under `GRENADE.gravity` and moves in up to three straight legs by `CollisionWorld.raycast`, each ending where it hits; it's put back its size out along the surface normal (not back along its path, which leaves it in the floor on a glancing hit), and bounces with `restitution` into the surface and `friction` along it. Slow on a floor (normal y above 0.7), it rests until the floor goes. A blast's share per character (`blastShare`) is by distance to the nearest point of a line from shins to head, if a ray reaches that point, the chest or the head; each zone then goes through `woundZone` (`sim/health.ts`), the armor-and-bleeding half of `shootCharacter`. Enemies run from them in `fleeGrenade` (`sim/ai.ts`): it runs before the activity switch in `behave`, so whatever the enemy was doing resumes with a fresh path once the grenade has gone off. The client draws them in `render/grenades.ts`.
  - **Effects (2026-10-31):** optional `effect` (`frag`, `flash`, `smoke` or `c4`; `grenadeEffect` reads it, frag when left out), `blindTime` (flash only) and `smokeTime` (smoke only), both checked in `checkItems`; `damage` may be 0. In `explode`, a flash blinds (`Character.blind`, seconds, counted down in `step`; optional for older saves) whoever is within the radius facing within `GRENADE.flashAngle`, with a clear ray to the eye and `smokeBlocks` false. A smoke pushes a `Smoke` (`SimState.smokes`, aged in `updateGrenades`, missing in older saves until the client adds it); `smokeRadius` gives its size now and `smokeBlocks` tests a segment against every cloud (nearest point to each middle). C4 gets `Grenade.remote`: `moveGrenade` stops it dead on its first hit and leaves it there, its fuse doesn't run until `PlayerInput.detonate` deletes `remote` on all of the thrower's. `PlayerInput.grenade` picks the kind `carriedGrenade` returns. `roundOf` returns null for C4, which keeps it out of every launcher path.
- **ammo → flame (2026-10-31, still format 9: an optional field and a looser check):** flamethrower fuel has `flame: { speed, burnTime, burnDamage, fireTime }` (m/s, s, HP/s per zone, s), and then `damage` 0 (the schema requires damage above 0 for every other round, and 0 only with `flame`; no pellets). The sim is `sim/fire.ts`: `fire` in `sim/weapons.ts` calls `launchFlame` for such a round, pushing a `shot` event that goes nowhere with the flame's id in `ShotEvent.flame` (0 otherwise; no tracer or whizz). Flames are `SimState.flames` (`Flame`, `left` in meters), moved by `updateFire` after the grenades: gravity `FIRE.gravity`, a world ray and `raycastCharacters` (skipping the shooter) each tick; a character hit is `ignite`d, a map hit lights a `FirePatch` (`SimState.fires`, merged within `FIRE.merge`, capped at `FIRE.maxPatches`). Touching one (`patchRadius` + body radius from a line feet to top) ignites. `Character.burn` (`Burn`: seconds left, by, fuel item) takes `burnDamage` a tick from every zone through `dealDamage` (no armor, no damage events: like bleeding), with `by` so a death is credited. `PlayerInput.extinguish` starts `Character.extinguish` (`updateExtinguish`, in step's hands-and-meds loop): `FIRE.extinguishTime` seconds, which blocks `updateWeapon` (fire, aim, reload), `updateMelee`, `updateThrow`, meds and switching hands, caps walking at `MOVEMENT.extinguishSpeed` and stops sprinting. An `IgniteEvent` marks a new fire (not one lit again). All optional on older saves (the client adds the lists). AI: `ignite` alarms like damage; `behave` presses extinguish while alight and steers straight out of fire (`inFire`); `findPath` takes an optional `Avoid` (spots, radius, extra cost per node; smoothing won't cut through one), and `moveTo` passes the fire, keeping `AiState.fires` (the newest fire id planned with) so `fireAcross` re-plans when newer fire lies across the rest of the path. The client draws it all in `render/fire.ts`: two `InstancedMesh`es of camera-facing squares (`Sprites`), flames and smoke, so two draw calls. The flames' texture is one SVG sheet of four flame frames and a glow; each instance has `aFrame` (which cell) and `aFade` attributes, read by a `MeshBasicMaterial` patched in `onBeforeCompile`, and flames are drawn premultiplied with `COVER` 0.7 (blend One, OneMinusSrcAlpha), partly additive. Licks and smoke puffs are worked out from the time and a seeded hash each frame, with nothing stored. Anything within `NEAR`–`FAR` of the camera fades out. `#burn` is the player's own fire, using `FIRE_SVG` without the blur filter: a blurred SVG as a CSS background slowed the screen badly in headless Chrome. At the start of a raid `play/index.ts` draws that SVG once into a canvas at the size it's shown (70 × 140 CSS px, times the pixel ratio up to 2) and uses the bitmap: left as an SVG, the browser drew it afresh for each flame in the row the first time you caught fire, a stall of most of a second (decoding it up front didn't help, since an SVG is drawn again for each size it's shown at). The damage log reads a burn's numbers with `burnOf`, never `ammoDef`: what lit you may be a molotov.
- **Molotovs and incendiary rounds (2026-10-31, still format 9: optional fields):** grenades gain effect `molotov` with `fire: { burnTime, burnDamage, fireTime }` (`checkItems`: a molotov needs it, and only it); `roundOf` returns null for a molotov, as for C4. Ammo gains optional `incendiary: { chance, burnTime, burnDamage }` (not with `flame`). `burnOf(items, id)` reads how anything sets alight (fuel's `flame`, `incendiary`, a molotov's `fire`) and `fireTimeOf` how long its fire burns on the map, so `Burn.item` and `FirePatch.item` may be any of them. `updateThrow` launches a molotov with `armIn` 0, an impact fuse armed from the hand, so it breaks on its first map or character hit; `explode` calls `spillFire` (`sim/fire.ts`): the floor under it and `FIRE.spillRings` × `spillPer` spots, each dropped to a floor within `spillDrop` and skipped if a wall is in the way, each `light`ed. `castShot` (`sim/weapons.ts`) ignites a character it hits with `incendiary.chance`.
- **container → admin (2026-10-31, still format 9: an optional field):** `admin: true` marks a container for testing (`admin-backpack`): the admin page (`ui/admin-page.tsx`, `isAdminItem`) lists it on the Admin tab, not Gear.
- **weapon:** `ammo`, the round it comes loaded with (it fires any round of that caliber), `fireMode` (`auto` or `semi`), `rpm`, `magazine`, `reloadTime`, `aimTime`, `drawTime` (format 4), `range`, `loudness` (hearing radius in meters), optional `suppressed` (a built-in suppressor, 2026-11-05: no muzzle flash, no muzzle slot; `gunModel` reports it), `slots` (any of `optic`, `muzzle`, `magazine`), `hipSpread` and `aimSpread` (degrees), and `recoil` (`up` and `side` in degrees, `snap` and `recovery` per second; format 10 gave it `snap` and turned `recovery` from degrees a second into a rate, see Recoil; optional `angle` in degrees and `stableAfter` in rounds came in at 10 with no new version). **Grenade launchers** (2026-10-30, still format 9: an optional field changes no existing file): `ammo` may be a `grenade` item, and then `launchSpeed` (m/s) is required (`checkItems` checks both ways). Ammo and grenades are both **rounds** (`RoundDef`, `roundOf`, `roundCaliber` in `content/items.ts`): every grenade's caliber is `grenade`, so every launcher fires every grenade, and reloading, loading by dragging, unloading and selling treat grenades like any other round. Firing one (`fire` in `sim/weapons.ts`) calls `launchGrenade` (`sim/grenades.ts`, shared with the throw) instead of casting a ray, and pushes a `shot` event that goes nowhere (`hit: 'none'`, to = from) with the grenade's id in `ShotEvent.grenade` (0 for bullets); the client plays the gun's sound and muzzle flash for it but no tracer or whizz. Optional `armDistance` (meters, launchers only) gives its grenades an **impact fuse**: `Grenade.armIn` (optional, missing on thrown ones and older saves) counts down the meters flown; `moveGrenade` then returns true on the first map hit, or on a character (`raycastCharacters` along each leg, skipping the shooter), and `updateGrenades` explodes it there. A map hit before arming deletes `armIn`, leaving only the fuse.
- **Gun sway (2026-11-04):** `updateSway` in `sim/weapons.ts` sets `Character.swayYaw`/`swayPitch` (optional, players only, scaled by `aim`) from the tick and the turning since last tick; `fire` adds them to the shot, while melee and thrown grenades don't. Recoil stays one number in the sim: the frame draws `1 − AIMED_GUN_RECOIL × aim` of it on the camera (`AIMED_GUN_RECOIL` is 0.7 since 2026-11-04).
- **Breath (BW-1, 2026-11-12):** `updateBreath` in `sim/weapons.ts`, called from `updateSway` with whether the player is aiming in, keeps `Character.breath` (seconds held left), `breathOut` (breathing while aimed after running out, refilling at `BREATH.aimedRefill`; cleared by lowering or a full breath, and BW-2's button should set and clear it), `steady` (0 to 1, smoothstepped) and `exhale` (wobble seconds left), all optional (missing: full, 0, 0), and returns a scale on the idle sway. From the tick only, no random numbers. Tuning is `BREATH` (exported). The client's `#breath-ring` (`RaidHud.setBreath`) shows breath ÷ `BREATH.hold` while aim ≥ 0.5 and not full. BW-4's low stamina should shorten `hold` and slow `refill` here.
- **Recoil (2026-11-04, `sim/recoil.ts`):** `Character.recoilPitch`/`recoilYaw` are still what everything adds to the look (shots, melee, throws, the camera). Behind them, `Character.recoil` (`RecoilState`, optional, made at the first shot) holds the kick target, the spring's speed, the burst's round count and the time off the trigger. `fire` calls `kickRecoil` (one `nextFloat` per round, as before); `updateWeapon` calls `settleRecoil` once per tick **after** firing, which decays the target by `exp(−recovery·dt)` (× `RECOIL.afterBurst` once `idle` reaches `resetTime`) and steps the spring with its exact solution (stable at 30 Hz for any snap). Tuning is in `RECOIL` (first-round multiplier, reset time, damping, cap, stance and movement multipliers). `weaponStats` gives `recoilSnap` and `recoilRecovery` (recovery × attachments' `ergonomics`) alongside `recoilUp`/`recoilSide`. `kickRecoil` also takes the gun's `recoilAngle` and `recoilStableAfter`; `RecoilState.hold` keeps the kick target at the stable round. Nothing allocates per tick. The frame projects the sim's aim into camera space (exact under lean and pitch) and passes it to `Viewmodel.update` (`pointing` turns the gun about the eye) and `OpticOverlay.aimAt` (one reused `SVGTransform`, no strings).
- **Aim punch (TU-1, 2026-11-09, `punchAim` in `sim/recoil.ts`):** `woundZone` calls it after its `damage` event (in the infinite-health branch too), for players only (`!c.ai`). It adds straight to `recoilPitch`/`recoilYaw` (making `Character.recoil` if missing), so `settleRecoil`'s spring pulls them back to the kick target; capped by `PUNCH.most` on how far they already sit off the target, so many hits in a tick don't stack. The direction is a hash of `state.tick` and the id, not `state.rng`. No new state. The client (`hud/hit-direction.ts`) turns 4 pooled arcs in `#hit-dir` each frame with `hitBearing` against the camera's yaw, writing the transform only when the angle moves; `play/index.ts` adds a cosmetic `punchRoll` to the camera's roll.
- **Stocks (WF-1, 2026-11-12, still item format 10: optional fields and a new slot break no file):** `stock` is in `ATTACHMENT_SLOTS` (`content/models.ts`). A stock attachment has `stock: { length, foldedLength? }` (cells it adds to the gun's width, unfolded and folded); only stocks may. A weapon has optional **`defaults`** (slot → attachment id: what a new one comes with; `createWeapon` fits them before any asked for, so a loadout or offer listing another stock replaces it; `checkItems` checks each is that slot's and fits). A fold is `Fold` (`pivot` from the stock mount, `yaw`, optional `shift`): a stock's own `model.fold`, or the gun's `model.stockFold` (a folding mount, which folds any stock). `foldParts` turns parts about the upright axis through the pivot and adds the turn to each part's yaw (exact, yaw being outermost in YXZ); `gunModel` uses it for a folded stock. **Size:** `itemSize(items, item)` is a gun's `size` plus its stock's length (folded or not); grid code takes an `Item` now, not an id (`itemWidth`, `itemHeight`, `findSpot`). `Item.folded` (guns, profile-checked: only with a stock that folds) skips the stock in `weaponStats`; `detach` of a stock clears it. **Actions:** `{ type: 'fold', gun, folded }` (`setFolded`; the gun in hand gets `draw` of `FOLD_TIME`, not in the stash); `attach`, `movePart` and an unfold check `roomAs` (the cells the gun grows into, ignoring the part being moved). **Profile format 20:** every stored gun gets `stock`, the one it was modeled with (`STOCKS_IN_20`, frozen). `buyPrice` counts a gun's `defaults` not replaced by the offer. The split was done by a one-off script (stock parts picked by hand per gun, the mount at the stock's front; gun recoil up/side ÷ the stock's recoil, recovery ÷ ergonomics, aim time ÷ its aim time, width − 1, value − the stock's).
- **Footprints (WF-2, 2026-11-12, still item format 10):** an attachment's optional `rows` (magazine slot only) and `columns` (muzzle slot only), refined in the schema. `itemSize` adds the stock's length and the muzzle's `columns` to the width, the magazine's `rows` to the height; `roomAs` already covers any slot, so `attach` and `movePart` refuse growth with no room. The loot editor's sample grid uses `itemSize` too.
- **Magazines (MG-1, 2026-11-12, still item format 10):** a weapon's optional `feed: 'magazine'` makes it take **magazine items**: attachments in the magazine slot with `capacity` and `caliber` (both or neither; such a part must list its `weapons`, adds no `mods.magazine`, and `checkItems` holds each listed gun to taking magazines and to its caliber). A magazine-fed gun must come with one (`defaults.magazine`) whose capacity is its `magazine`, which is then only for the editor's numbers: `weaponStats` takes the fitted magazine's capacity (0 with none). **State:** the fitted magazine is still just its id in `attachments.magazine`; its rounds are the gun's `mag` and `loaded`. A loose magazine is an `Item` with `mag` and `loaded` (both or neither; `checkMagazine` in profile.ts). `partOut`/`partIn` (`sim/weapons.ts`) move a part between gun and loose item, a magazine with its rounds; `attachPart`, `detachPart`, `movePart` and `strip` use them for magazines. **Reloads:** `usesMagazines(state, c, def)` (a magazine-fed gun, a player, not `state.zombies`, no free ammo); then `startReload`/`finishReload` take the fullest fitting magazine in `QUICK_GRIDS` (`findMagazine`, no allocation; the round asked for first), re-picked at the finish, and stow the old one in pockets/rig or drop it. `PlayerInput.quickReload` (a press; the client's `Controls` sets it on a second reload press within `DOUBLE_TAP_MS`) starts or converts a reload to `WeaponState.reloadQuick`: `RELOAD.quick` (0.7) of the time, the old magazine dropped. Otherwise (enemies until MG-3, zombies, free ammo) loose rounds go into the fitted magazine as before. `loadKind`/`loadGun` load a loose magazine or a gun's fitted one at once, one round type; `unload` empties a loose magazine. `spareRounds` is the HUD's count. `restGear` only touches guns now (a loose magazine has `mag` too); `sellParts` counts a magazine's rounds; `plainItem` refuses a loaded one. **Profile format 21:** a stored magazine-fed gun with none fitted gets its own (`MAGS_IN_21`), holding what it had loaded. Starting-kit stacks may give a magazine's `loaded` round (it comes full). The split was a one-off script, as for stocks: a gun's parts `hiddenBy: 'magazine'`, or ones picked by hand, became `<gun>-mag` (mount at the first part's top), worth 1,500 (pistols), 2,500 or 6,000 (belt boxes), taken off the gun's value; the 5.45 AK magazines fit the AK-74M, AKS-74U and RPK-16.
- **Packing (MG-2, 2026-11-12):** `sim/packing.ts`. `Character.packing` (missing when idle) is a job: `pack` (Pack Mags, re-picks the target each round: `packTarget`), `load` (a stack onto a magazine or a magazine-fed gun, `mag` + `from` refs) or `unload` (`mag`); `next` seconds to the next round, `done`/`total` for the bar (`packable` plays Pack Mags out). `updatePacking` runs in step after meds, before weapons, so a fire input stops it and still fires. Timed only for players outside zombies mode in a raid (`packingTimed`); the stash, enemies and zombies stay instant. Inventory action `{ type: 'pack', stop? }`; `load` and `unload` start a job when timed. Rates in `PACKING`. No item stat, so nothing for the item editor.
- **Enemies' magazines (MG-3, 2026-11-12):** `usesMagazines` no longer exempts the AI (zombies mode and free ammo still do). `canReload` (weapons.ts) is what the AI's `reloadIfLow` asks. With no fuller magazine in reach, an enemy's reload sets `WeaponState.reloadLoose` and loads loose rounds the old way (`looseReload`, `RELOAD.aiLoosePerRound`). `equipLoadout(…, magazines)` stows the spare magazines (`stowMagazines`, `SPARE_MAGAZINES`); waves and squads pass `!state.zombies`. `packingTimed` would time enemies too, but they never pack since MG-4.
- **MG-4 (2026-11-12):** `MOVEMENT.packSpeed` (2 m/s) caps a character with `packing`. Enemies: `magRounds` (weapons.ts) counts a magazine as topped up from loose rounds, in `findMagazine` (which takes empty ones for an enemy) and `worthSwap` (the swap rule, in `canReload` and `startReload`); `finishReload` takes the rounds as it goes in. `updateAi` no longer starts packing (MG-3's hook removed). Quick equip's magazine path: `magRoundFor`, `chosenMags`, `fillRound`, `equipMagGun` in `stash-quick-equip.ts`.
- **Headsets and helmet senses (GZ-2, 2026-11-12, still item format 10: a new type and optional fields):** type `headset` (`hearing`, a share 0–1). ## Inventory model
Session 9. All in `packages/shared`, plain JSON-safe data like the rest of the state, so a co-op server can run it and the stash (session 13) reuses it.
- **`Item`** (`inventory/grid.ts`): one item or a stack wherever it is: `item` (the definition's id) and `count`, plus whatever its type needs: `durability` (armor), `left` (uses or HP left in a med, points in a repair kit), `mag` and `attachments` (guns), `grid` (rigs and backpacks). The sim's narrower types are Items with those fields required: `WeaponState` (which also keeps the reload and fire timers), `ArmorState`, `ContainerState`. So an item moves between a slot and a grid as the same object, with no conversion. `createItem` (`sim/create-item.ts`) makes a new one with the fields its type needs.
- **No item instance ids.** An item is found by its grid and index (or its gear slot). Nothing needs a lasting id yet: the heal button picks by state, not by a bound item. Add ids if co-op looting needs them.
- **`Grid`**: `w`, `h`, `containers` (whether rigs and backpacks may go in: true only for the stash and loot containers) and `items`, each with `x`, `y` (top left) and `rotated`. There's no occupancy array; overlap is checked against the item list, which is short. Operations: `findSpot`, `placeAt`, `addItem` (auto-placement with stacking), `dropAt` (drag and drop, merging stacks), `rotateAt`, `transfer` (double-tap), `countOf`, `takeFrom`, `removeAt`.
- **`Gear`** (`sim/gear.ts`) is `Character.gear`: `primary1`, `primary2`, `sidearm`, `knife`, `helmet`, `bodyArmor`, `rig`, `backpack`, `pockets` (4×1) and `vault` (2×3, null for enemies), and `hand` (which gun slot or the knife is out). **`heldWeapon(c)` is the gun in hand**; there's no separate `weapon` field, which would turn into a second copy after a JSON round trip. `equip` and `unequip` check what fits each slot; `switchHand` puts the gun away (its reload stops). `carriedGrid(gear, i)` walks pockets, rig and backpack by index, so `carriedAmmo` and `takeAmmo` (reloading) allocate nothing.
- **`attach` and `detach` return the rounds that no longer fit** the gun (a smaller magazine) for the caller to `stow`.
- **Meds** (`sim/meds.ts`): `treatments(c, items)` lists what the heal button offers, best first, as `MedRef`s (grid, index and item id); `useMed` applies one use. `Health` gained `splinted` per zone; `isBroken` is false for a splinted limb, but `dealDamage` still spills over from any limb at 0 HP.
- **Loadouts** gained optional `rigs` and `backpacks` (worn empty; since session 11 the enemy type's loot goes in them). A rolled gun goes in the sidearm slot if it's a pistol, otherwise the first primary, and the spare rounds are stowed (pockets, then rig, then backpack; what doesn't fit is left out). The format stays 1, since the new fields are optional.

## Hands, meds and the knife
Session 10b, in `shared` like the rest of the rules.
- **State:** `Character` gained `draw` (seconds left drawing what's in hand), `swing` (seconds until the knife can swing again) and `using` (`MedUse`: the med's grid, index and item id, and the seconds left, or null; since 13b also a repair kit's, with the `armor` ref). All plain numbers, so a save mid-heal or mid-draw restores exactly (tested).
- **Inputs:** `PlayerInput` gained optional presses `draw` (a hand slot) and `use` (a `MedRef` to start, or `'cancel'`). Optional, so AI inputs and tests don't change; enemies never switch or heal.
- **Tick order:** inventory actions, then for everyone the draw timer, a `draw` press (`switchHand(c, items, hand)`, which takes `drawTime`), and `updateMedUse` (start or cancel, the canceling conditions, the timer, then `useMed`); then movement (capped at `MOVEMENT.useSpeed` while using, ×`knifeSpeed` with the knife out); then each character's gun (`updateWeapon`: no firing, aiming or reloading until drawn; no aiming while using) and knife (`updateMelee`).
- `equip` into the slot in hand starts a draw too (a gun dropped into your hands from the inventory). `giveWeapon` leaves it ready, for spawning.
- **The knife** (`sim/melee.ts`): a swing casts up to five rays from the eye (the look with recoil, then `MELEE.fan` up, down, left and right), each against the world and then characters within reach; the first that reaches a body part wins. It hurts through `shootCharacter`, which now takes a `Wound` (the damage, armor damage and bleed chance that ammo and melee items share) and a cause (`shot` or `melee`). A `swing` event (hit or miss, and where) drives the slash animations and impact puffs; there's no loudness, so AI hears nothing.

## Looting and inventory actions
Session 10. `sim/looting.ts` in `shared`.
- **Loot containers** are `SimState.loot`: each has its marker's path id, its kind (`content/loot-containers/<id>.json`: `name` and `grid`, format 1), its position and a grid that takes rigs and backpacks. `placeLootContainers` makes them from a compiled map. Dead bodies aren't copied anywhere: you loot their `gear`.
- **Inventory actions** go in `PlayerInput.inventory` and are applied at the start of `step`, before movement, each giving an `inventory` event with `ok`. So a co-op server can apply them in the same place, and the raid doesn't have to pause. An action names an `Owner` (`self`, a `body` by entity id, or a `container` by id), then a grid (`pockets`, `rig`, `backpack`, `vault`, or a container's `loot`) and index, or a gear slot, **plus the item id the sender saw**, so an action that has gone stale fails instead of moving the wrong thing. Reach (`LOOT_REACH`, 2 m across and up or down) and "the body is dead" are checked by the sim, not the UI.
- The client keeps one array of pending actions as the player's `inventory` input and empties it after each tick, so ticks allocate nothing.
- **Attachments (session 10c):** `attach` (`gun`, `from`: a loose attachment in a grid, or a `PartRef` (`gun`, `slot`, `part`) for one on another gun) and `detach` (`gun`, `slot`, `part`: the attachment id the sender saw, `to`: a `GridSpot` or null for what you carry). The gun can be anywhere you can reach: your slots or grids, a body's, a container's. A loose attachment is a plain `Item` made with `createItem`; on the gun it's only its id in `attachments`. When `attach` replaces a part, the old one goes where the new one was (same cell, either way round), else anywhere in that grid, else into what you carry. Rounds a smaller magazine hands back go into **the acting player's** carried grids, never the vault. From another gun (`movePart`), the second gun's old part goes onto the first if it fits there, else into what you carry, and both guns' handed-back rounds are checked together. Since session 11b, what has nowhere to go (the rounds, a displaced part, a part taken off into what you carry) is **dropped at the player's feet** instead of the action being refused, so `roomForRounds` and the undo are gone. Allocating here is fine: it's once per action, not per tick.
- **Items on the ground (session 11b, `sim/ground.ts`):** `SimState.ground` is a list of `GroundItem`s (the `Item`, its position and a yaw for drawing), plain data like the rest. The ground is an `Owner` (`{ kind: 'ground' }`); an item on it is an `OnGround` ref (its index in the list, plus the item id the sender saw, like grids), and a `Target` can be `{ owner: { kind: 'ground' } }`. So the existing actions cover it: `quick` from the ground to `self` picks up (the use button sends this), `quick` or `move` to the ground drops, and `move` from the ground to a gear slot swaps, leaving the old item where the new one lay. Each ground item must be within `LOOT_REACH` (`groundInReach`). `dropItem(state, c, item, world?)` places a drop 0.9 m ahead (or at the feet if a raycast at knee height finds a wall), scattered with the sim's RNG, on `world.groundAt` below; so `applyInventory` takes the world as an optional last argument, and `step` passes it.
