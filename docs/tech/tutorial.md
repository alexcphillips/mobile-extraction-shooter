Part of the [tech-stack.md index](../tech-stack.md). Record decisions here, in the topic they belong to.

## Tutorial
TU-2, 2026-11-09. See design.md → Tutorial for the flow.
- **`content/tutorials/<id>.json`** (`content/tutorials.ts`, format 1): `raid` (an offline raid config), `kit` (a starting kit: its gear, `carried` and `loaded`/`fitted`; money and stash unused) and `steps`, each `{ id, prompt: { touch, gamepad, desktop }, trigger, marker? }`. Triggers: `moved` (`distance` m from where the step began), `zone` (a map zone by id, extraction or not), `vault` (a vault, or going up in a jump), `crouch`, `carry` (`item` in a gun slot, worn, or in pockets, rig or backpack), `notBleeding`, `kill` (an enemy killed by you), `reload` (started), `searchBody` (a `RaidState.searches` entry for a body), `door` (a door's path id, unlocked or opened by you), `extract` (your `leave` event). `marker` is a `questMarker`'s path id to point at.
- `compileTutorial(def, map)` looks up zones' outlines, doors' indices and markers' positions, failing on anything missing; the client's `loadTutorial(id)` also checks the raid is offline, the kit exists and `carry` items exist.
- **Following it (`tutorial.ts`, shared):** `startTutorial(player)` gives a `TutorialProgress` (`step`, and `fromX`/`fromZ` for `moved`), plain data to save with a snapshot. `advanceTutorial(t, progress, state, playerId)` after **every tick** (events last one tick) moves past the showing step if its trigger happened, and past any after it already true (a heal step with nothing bleeding), and says whether it changed. It reads the state and changes nothing.
- `packages/client/src/tutorial.test.ts` plays it through in the sim as a scripted player: the vault, the gap (refused standing), the wire's bleed, the bandage at its marker, the scav, the key, the door, the yard.
- **Steps' `buttons`** (TU-3, optional): HUD control ids (`hud/layout.ts`) to outline while the step shows; `loadTutorial` fails on an unknown one.
- **The client (TU-3, 2026-11-09):** `tutorial-seen.ts` keeps the device's flag (`mes.tutorialSeen` in local storage; unreadable storage counts as seen). main.ts: `firstLaunch()` (not seen, and `fetchProfile` null or offline) runs `playTutorial` instead of the menu; `prepareMenu` sets the flag once someone is signed in. `?tutorial` plays it (Settings' replay); it leaves to `/?signup`, and `showAccount(container, 'register')` opens on creating an account; both params are stripped from the address. `startPlay` takes `tutorial: { def, leave }`: the raid as usual on its offline config but no quests, snapshot, server result or Give up; `advanceTutorial` after each host tick; the end is a result with `tutorial: true` (its own results screen, whose Continue calls `leave`). `hud/tutorial-card.ts` (`TutorialCard`, in `#tutorial`, above `#raid`) draws the card (`inputMode` picks the prompt), the marker (`screenSpot`, shared with quest markers) and the `.tutorial-hint` outlines. `skipTutorial` (`play/give-up.ts`) is set while one is going, and the settings screen shows Skip tutorial for it; `onReplayTutorial` only from the menu.
